# Fanout v3.1.0-live-engine

本版本基于用户上传的 `2112-main/fanout-main` 全量源码做了代码审计、节点测活链路重构和前端任务展示精简。

## 关键修复

- OpenVPN 测活不再把“远端端口可连接”当作节点成功。
- OpenVPN 候选现在先快速端口门槛，再执行真实 OpenVPN 握手；握手成功才进入 live 节点列表。
- SOCKS5/HTTP 测活要求完成代理协商、CONNECT 和实际 HTTP 回包。
- 修复上游代理出网验证失败后仍使用节点 IP 伪装成成功的问题。
- 健康检查对代理出口 IP 做一致性验证，避免代理已经回落/断流但仍显示 UP。
- 健康检查改为可停止 ticker，并清理已经不存在的 slot 状态。
- 节点身份键加入协议，避免相同 IP/端口但不同协议被错误合并。
- 单来源刷新不再清空其它来源及自建节点池。
- 实时扫描改用统一来源过滤逻辑，并修复同 IP 节点被过度去重的问题。
- live API 不再只检测排序最前的一小批死节点；会扩大候选窗口后再筛选真正通过的节点。
- 国家实时节点统计增加候选抽样数量，但仍有硬上限避免移动端等待过久。
- 智能编排改为“并发测活 → 少量正式启动 → 最终真实出口验证”，减少大量死节点导致的串行等待。
- OpenVPN 正式启动的连接等待上限收紧，减少单个死节点长时间拖住编排。
- 任务卡片不再渲染数百个红色失败按钮；失败节点自动隐藏/冷却，只显示轻量统计。
- 删除前端已经不再需要的“显示全部爆红/逐项展开/清理爆红”交互代码。
- 增加节点身份键单元测试。

## 重要说明

OpenVPN 的 live 测活现在依赖服务器上可执行的 `openvpn`。这是有意的：如果服务器本身无法运行 OpenVPN，就不能把仅仅“端口可达”的 VPN Gate 节点标记为真正可用。

最终正式出口仍然必须再次建立真实隧道并取得实际公网出口 IP；live 测活只是前置过滤，不会绕过最终验证。
