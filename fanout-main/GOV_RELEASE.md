# 政府/公共机构疑似候选更新

版本：`v3.2.1-gov20261018`，2026-10-18。

本版包含此前全部修复、出口数量设置及默认 80% CPU/内存保护，新增政府/公共机构疑似候选的统一筛选与展示。

## 本次修改

上一版 `gov` 筛选只接受管理员声明授权并提供说明链接的来源，因此公开列表和旧缓存里仅带机构标签的疑似候选会被排除。

本版在新建出口与测活来源中提供三个选项：

| 选项 | 范围 |
|---|---|
| 政府/公共机构（含疑似） | 管理员声明来源和公开元数据疑似候选 |
| 仅疑似政府/公共机构 | 公开源、历史标签、运营商名称、主机名等机构线索 |
| 仅管理员声明授权来源 | 管理员设置政府分类并提供政府官方域名上的说明链接；链接内容和实际授权未独立核验 |

智能编排的政府复选框采用“含疑似”范围，全部来源也包含这些候选。地区列表、候选列表、测活、编排共用相同规则。来源管理增加“刷新政府/公共机构候选（含疑似）”，刷新时从现有全部公开和自定义来源聚合后按分类筛选。

候选及出口行显示“疑似机构 · 未核验”或“管理员声明授权”，鼠标提示显示分类依据。身份线索与真实拨号可用性分别处理：疑似标签不能证明政府所有权、访问授权、匿名性或稳定性；加入运行出口仍要通过现有预检/实际出网验证。

保留公开来源自报的主机名、Operator/Message 线索与历史 `Source=gov`、`IPType=gov` 标签。缓存新增机构分类依据、ISP 与 IP 类型字段，刷新、同端点去重和重启时保留疑似线索；新元数据不再提供同一线索时，保留项标为“历史元数据（可能过期）”。不同协议/IP/端口之间不传递分类依据，管理员授权声明也不会转移给另一个公开来源。

修复启动读取缓存按 IP 合并、遗漏同一 IP 不同端口配置的问题。完整刷新结果保存到缓存，包含管理员来源和分类依据。公开 CSV 的机构关键词匹配不再虚构国家机构 ISP 名称，也不因为该标签强制赋 99 分。

你记得的四个节点如果仍在当前公开来源或 VPS 缓存中，并具有相应线索，会进入“含疑似”范围。节点离线、缓存已丢失、当前来源不再列出或质量/配置检查未通过时，不能保证四个节点全部恢复，更不能保证当前实际数量。

## 升级

上传完整 ZIP 到 `/root/fanout-v3.2.1-gov-20261018.zip`，执行：

```bash
python3 -m zipfile -e /root/fanout-v3.2.1-gov-20261018.zip /root/fanout321
bash /root/fanout321/2112-main/fanout-main/upgrade-local.sh
```

脚本验证程序校验和及版本，自动备份到 `/var/backups/fanout-upgrade.*`，连接会短暂中断；启动失败尝试回滚旧程序。不会改写现有服务启动参数。

升级后强制刷新网页，打开“节点源”选择“刷新政府/公共机构候选（含疑似）”；在新建出口或测活里选“政府/公共机构（含疑似）”，再运行测活。旧缓存会读取，勿先清空缓存。是否成功连通以 VPS 真实出网验证为准。

查看内存占用可执行：

```bash
free -h
ps -eo pid,ppid,comm,rss,%mem --sort=-rss | head -n 21
systemctl show fanout -p MemoryCurrent -p MemoryPeak -p MemorySwapCurrent --no-pager
```

`RSS` 单位为 KiB；`systemctl show` 的内存值单位为字节，若系统不提供某属性会省略。fanout 服务的总量还包括其 OpenVPN/Xray 等子进程，单看主进程不足以反映服务总内存。
