# v3.2.0：出口容量、资源保护与来源管理

日期：2026-10-18。由原始附件 `2112-main (1).zip` 累积修复而来，包含此前 v3.1.1 和 v3.1.2 的修改。包内提供完整源码、Linux amd64/arm64 二进制、升级脚本、测试日志、逐文件修改清单与 SHA-256 清单。

## 可直接使用的变化

### 出口不再固定为 40 个

在页面顶部“容量与保护”中选择自动，或输入 1–254 的总出口上限。默认自动，仍受资源保护约束。254 是当前 IPv4 命名空间地址布局的技术上限，不代表 VPS 能承担 254 条连接，也不代表有足够可用上游。

默认每秒采样，CPU **或**内存达到 80% 时暂停新建出口；页面可将阈值调整为 50–95%，也可关闭保护。读取不到资源、CPU 尚未完成首轮采样、采样超过 5 秒未更新时，保护开启的情况下暂停新增。识别主机内存以及较严格的 cgroup v1/v2 内存限制，支持 cgroup v2 CPU 配额。面板显示出口额度、待恢复数量、CPU、内存、Swap 和暂停原因。

所有新建入口共用准入检查，涵盖手动新建、智能编排、测活后批量启动和状态恢复。最多两条处于启动阶段，新增启动间隔至少一秒。降低上限不会删除现有出口；待恢复条目继续保存在状态文件中，待有额度和资源时恢复，避免重启丢失。

这是采样后的新增限制，不是操作系统硬资源限额。已有连接负载增长、进程启动的短时峰值、后台测活与抓取仍可能使占用超过阈值；不能承诺始终不超过 80%。

若现有 systemd 的启动命令显式带 `-max 40` 或其他数值，该参数在每次重启时优先于保存值。面板修改在当前进程立即生效；要长期以面板为准，需移除旧的显式 `-max`。升级脚本不会自行改写现有服务文件。

### 新的来源管理

新增最多 20 个 HTTPS 授权来源，支持单个 OpenVPN 配置、ZIP、VPN Gate CSV 和 JSON 配置清单。可设置国家代码、分类、用户名和密码，查看最近抓取时间、有效配置数量及错误。保存来源后需刷新候选池。

密码接口不回显，空白编辑保留旧密码，只有勾选清除才删除；配置、状态与缓存文件使用私有权限。停用或删除来源会排除后续候选，不中断已运行出口。旧自定义来源列表现在持久化，重启后保留。

下载具有超时、响应大小和重定向限制；ZIP 在内存中读取，不向文件系统解压来源中的路径，对单配置、条数与解压总量设限。只接受通过项目配置白名单校验的 OpenVPN 配置。这不是任意文件订阅器；JSON 条目需要提供有效 IP、端口与配置。

修复了 VPNBook 官方下载方式变更造成旧抓取器失效的问题。新实现从官方网站获取当前公开凭据及配置，不硬编码轮换密码。实测成功下载、校验 10 份官方配置；未执行 VPN 握手，不能把它当作 10 个已验证可用出口。

来源依据：

- [VPN Gate 官方](https://www.vpngate.net/en/)：公开志愿者 VPN。由大学开展项目不代表每个服务器属于大学或政府。
- [VPNBook 官方 OpenVPN 页面](https://www.vpnbook.com/freevpn/openvpn)：当前配置与公开轮换凭据的获取入口，本次实际抓取验证。
- [Proton VPN 官方配置下载说明](https://protonvpn.com/support/vpn-config-download)：账户配置需要用户自行取得，可作为授权配置导入；本版没有自动登录其账户。

没有找到并验证可供公众使用的新增政府出口，因此没有宣称加入政府专网。新增的政府分类要求管理员提供政府官方域名上的授权说明链接；程序仅校验 URL 和域名格式，**不独立核验网页内容、机构身份或实际授权**。该标签不构成可信度证明。已有按网络信息推测的机构分类在界面上明确标为推测，不等同于授权政府来源。不扫描政府网络，也不将普通公网 IP 冒充政府节点。

### 功能之间的修复

- 出口总数与命名空间槽位分离计算；旧的高编号隧道继续占用总额度，避免降低上限后重复挤占。
- 重启恢复改为队列；待恢复数据不因中途保存状态丢失，保留端口、SOCKS 凭据、上游协议和服务商凭据。
- “停止全部”现在清空待恢复队列，也能处理尚未连接成功的出口，并显示失败原因；避免刚停止又被旧队列恢复。它不关闭启用的自动策略，后续策略仍可能新建出口。状态保存对活动出口与待恢复队列采用同一份锁内快照，避免恢复迁移时漏存条目。
- 节点缓存补齐协议、端口、来源、授权说明和服务商凭据，修复代理节点重读为 OpenVPN、CSV 中逗号破坏字段的问题。缓存统一按协议/IP/端口去重。
- 每条隧道独立的 OpenVPN 凭据文件，避免不同服务商并发启动覆盖共用文件。握手预检也使用对应凭据。
- 编排、测活筛选及托管来源共用来源分类规则；“全部来源”真正包含全部候选，添加 Riseup 选项。没有将参考评分作为安全保证。
- 资源阻挡作为本机准入错误处理，不把节点记入故障冷却；批量启动使用任务队列，并保留真实暂停原因。
- 智能编排重复请求接入现有任务返回 202，不再误报失败 409；保留旧服务端 409 的前端兼容。
- 智能编排、测活启动、批量启动的 GET 请求返回 405，防止普通读取触发这些操作。
- 设置先校验再更新，非法端口等参数不再顺带修改密码；仅修改运营商策略也能正确保存。
- 健康检查和恢复任务响应停止信号；出口 IP 与健康检测请求改用 HTTPS。
- 保留此前对鉴权、配置输入、Worker 鉴权及缓存隔离、更新脚本等已确认问题的修复，详见历史报告和 CHANGE_LIST.json。

### 网页面板

增加资源面板、容量设置、来源编辑与明确的同步失败提示。隐藏页面暂停定时刷新，阻止同类刷新重叠；编排完成的进度条显示完成。改善窄屏布局、减少动态效果模式、背景样式降级、弹窗 Escape 关闭、焦点恢复与键盘焦点限制。修正文案中“绝对纯净”“极速防封”和未经验证的机构身份等表述。

本地浏览器使用实际页面配合模拟接口，完成自定义数量保存为 120、来源新增保存的操作验收；`panel-preview.png` 是模拟数据截图，**不是 VPS 运行截图**。

## 未解决风险与上线验收

1. 实际 Linux 隧道、网络命名空间、防火墙、Xray、外部面板账户及真实节点链路仍需在目标 VPS 验收。公开节点会失效，参考评分不能证明质量或隐私。
2. 未完成全程序竞态验证；历史可变隧道字段及并发状态路径仍需 Linux race 测试/压力测试。没有宣称所有选项与组合已证明正常。
3. 来源格式/官方网站可能继续变化；单来源有超时，多个自定义来源顺序抓取可能使整轮刷新较慢。旧的其他公开来源本轮未逐一验证。
4. 资源保护约束新增，不自动杀掉旧连接，也不自动降低现有数量。Swap 不作为独立阻挡阈值；实际可承载数量需结合 VPS 内存、CPU、系统限制和上游质量确定。
5. 设置的多文件写入不是完整事务；校验失败的部分修改已修复，极端磁盘故障下仍可能需要从备份恢复配置。
6. 上传后先查看版本、服务状态及资源读数，再以较小数量创建真实出口，确认出口 IP、节点链接、轮换和重启恢复后再逐渐增加。已有连接可能因为资源阻挡而延后恢复。

## 已有 VPS 原地升级

将完整 ZIP 上传到 `/root/fanout-v3.2.0-resource-20261018.zip`，执行：

```bash
python3 -m zipfile -e /root/fanout-v3.2.0-resource-20261018.zip /root/fanout320
bash /root/fanout320/2112-main/fanout-main/upgrade-local.sh
```

脚本先校验两种架构文件的 SHA-256 和本机程序版本，保存旧程序、服务定义及私有运行数据备份到 `/var/backups/fanout-upgrade.*`，停止并替换 fanout 后启动。连接会短暂中断，不清空配置、不下载上游程序、不重写现有服务。启动失败会尝试回滚程序；完整运行数据备份不会在正常升级中自动覆盖回去。服务启动通过不等于 VPN 出口通过验证。

升级后强制刷新页面，检查版本为 `v3.2.0-resource20261018`；在“容量与保护”里设置数量或使用自动模式，默认 80% 保护。来源管理保存后刷新候选池。不要运行历史远程安装链接覆盖本地修复版。

复查可运行 `bash check.sh`。支持 cgo/C 编译器的 Linux 环境可运行 `FANOUT_RACE=1 bash check.sh`；外网来源单独运行 `FANOUT_TEST_LIVE_SOURCES=1 go test -run TestVPNBookOfficialFeedLive -v -count=1`。
